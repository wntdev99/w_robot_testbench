# 메인 페이지 패러다임 — 와이어프레임 10안

> `w_robot_testbench` 웹툴의 **메인(랜딩) 페이지** 구성을 정하기 위한 후보 10안.
> 각 안은 ASCII 와이어프레임 + 개념 + 장단점 + 본 프로젝트 적합도(6카테고리: 시스템/런치/텔레옵/모터·제어/전장부/데이터)로 평가한다.
> 공통 전제: 브라우저로 `http://192.168.34.202:<port>` 접속, Toss풍 UX, 실시간 WS 스트림.
> 범례: `●`=정상/연결, `○`=메뉴항목, `▶`=실행, `■`=정지, `⊞`=추가, `⌘K`=커맨드팔레트

---

## 1안. 사이드바 콘솔형 (Sidebar Console)

좌측 고정 내비(6카테고리) + 상단 글로벌 상태바 + 우측 콘텐츠. 가장 보편적인 운영 콘솔 구조.

```
┌───────────────────────────────────────────────────────┐
│ w_robot_testbench     ● zenoh   ● 201 함께   CPU23% ⚙ │  ← 상단 글로벌 상태바
├──────────────┬────────────────────────────────────────┤
│ ◉ 시스템      │                                        │
│ ○ 런치        │     [선택 카테고리 콘텐츠]              │
│ ○ 텔레옵      │                                        │
│ ○ 모터·제어   │     예) 모터·제어                       │
│ ○ 전장부      │       ├ joint_states 실시간 플롯        │
│ ○ 데이터      │       └ controller 스위치 / 직접명령    │
│ ───────────  │                                        │
│ 프로파일 ▼    │                                        │
│  ▶ 텔레옵     │                                        │
│  ▶ 모터테스트 │                                        │
└──────────────┴────────────────────────────────────────┘
```
- **장점**: 6카테고리 항상 노출, 컨텍스트 전환 빠름, 상태바로 zenoh/201 상시 확인. 학습 부담 최소.
- **단점**: 랜딩이 "기능 나열"이라 첫인상이 평범. 모바일 협소.
- **적합도**: ★★★★★ — 다기능 운영툴의 정석. 데이터 페이지 안에 도킹 플롯을 품기 좋음.

## 2안. Toss풍 홈 대시보드 (Dashboard Home)

랜딩 = 상태 요약 카드 + 빠른 시작 버튼 + 즐겨찾기 플롯. 카드 클릭으로 상세 진입.

```
┌───────────────────────────────────────────────────────┐
│  안녕하세요 👋   로봇 상태를 한눈에                     │
├───────────────────────────────────────────────────────┤
│ ┌─ 시스템 ──┐ ┌─ 활성 작업 ─┐ ┌─ 컨트롤러(201) ─┐    │
│ │● zenoh ON │ │  텔레옵      │ │  ● 연결 · 함께   │    │
│ │ CPU 23%   │ │  실행 중     │ │  control 실행중  │    │
│ │ 온도 47℃  │ │  3분 경과    │ │                  │    │
│ └───────────┘ └─────────────┘ └──────────────────┘    │
│  빠른 시작                                             │
│ [ ▶ 텔레옵 ] [ ▶ 모터테스트 ] [ ▶ 전장부 ] [ ⊞ 스냅샷 ]│
│  즐겨찾기 플롯                                         │
│ ┌─ joint_states ─┐ ┌─ BMS 온도 ─┐ ┌─ cmd_vel ─┐      │
│ │   ╱╲╱╲╱        │ │   ▁▂▃▅▇      │ │  ─╱──╲─    │      │
│ └────────────────┘ └─────────────┘ └────────────┘      │
└───────────────────────────────────────────────────────┘
```
- **장점**: 비전문가 친화적, "지금 상태/할 일"이 한 화면. Toss 감성에 가장 부합.
- **단점**: 심화 작업은 결국 하위 페이지로 이동 필요 → 단독으로는 부족, 내비 보강 필요.
- **적합도**: ★★★★☆ — 랜딩 홈으로 최적. 단, 1안 사이드바와 결합해야 완성도↑.

## 3안. 도킹 워크스페이스 (Docking Workspace · PlotJuggler류)

좌측 토픽 트리 → 드래그&드롭으로 플롯 패널 도킹, 우측 검사기/명령 패널. 플롯 중심 사용자에 최적.

```
┌───────────────────────────────────────────────────────┐
│ ●zenoh ●201 │ 프로파일:[텔레옵 ▼] ▶ ■ │ 스냅샷 저장 ⊞ │
├────────┬──────────────────────────────────┬───────────┤
│ 토픽    │ ┌── plot A ──┐ ┌── plot B ────┐ │ 검사기     │
│ /joint  │ │  ╱╲╱╲      │ │  ▁▂▃▅▇        │ │ pub │ srv │
│  ·pos[0]│ └────────────┘ └──────────────┘ │ ─────────  │
│  ·vel[0]│ ┌── plot C ───────────────────┐ │ controller │
│ /diag   │ │  cmd_vel  ─╱──╲──╱─          │ │  ◉ swerve  │
│ /cmd_vel│ └─────────────────────────────┘ │  ○ jsb     │
│ [드래그] │                                  │ [activate] │
└────────┴──────────────────────────────────┴───────────┘
```
- **장점**: 멀티 플롯 동시 비교, 자유 배치 → 스냅샷 저장과 궁합 최고. PlotJuggler 대체 목표 직격.
- **단점**: 초심자에겐 빈 캔버스 진입 장벽. 구현 복잡(도킹/드래그 레이아웃 엔진).
- **적합도**: ★★★★★ (데이터 페이지로서) / ★★☆☆☆ (랜딩으로서는 과함).

## 4안. 상단 탭 바형 (Top Tab Bar)

상단에 카테고리 탭, 그 아래 단일 작업 영역. 사이드바 대신 가로 탭.

```
┌───────────────────────────────────────────────────────┐
│ testbench   ● zenoh  ● 201      검색…           ⚙      │
├───────────────────────────────────────────────────────┤
│ [시스템] [런치] [텔레옵] [모터·제어] [전장부] [데이터] │  ← 탭
├───────────────────────────────────────────────────────┤
│                                                       │
│            [선택 탭 콘텐츠 영역 — 전체폭]              │
│                                                       │
│      예) 전장부: DALY BMS 전압/전류/온도/SOC 카드      │
│                                                       │
└───────────────────────────────────────────────────────┘
```
- **장점**: 콘텐츠 가로폭 최대 확보(와이드 플롯에 유리), 구조 단순.
- **단점**: 탭이 6개+면 모바일/협소화면에서 넘침. 하위 깊이 표현 약함.
- **적합도**: ★★★☆☆ — 와이드 플롯엔 좋지만 사이드바 대비 확장성 떨어짐.

## 5안. 커맨드 팔레트 중심 (Command-Palette First · ⌘K)

중앙 검색/명령창이 1차 진입점. "joint 플롯", "텔레옵 켜기", "BMS 보기"를 타이핑/선택해 즉시 실행.

```
┌───────────────────────────────────────────────────────┐
│                                            ● zenoh ●201│
│                                                       │
│              w_robot_testbench                        │
│        ┌───────────────────────────────────┐         │
│   ⌘K → │ 무엇을 할까요?  예: 텔레옵 켜기      │         │
│        └───────────────────────────────────┘         │
│         최근:  ▶ joint_states 플롯                     │
│                ▶ 모터테스트 프로파일                   │
│                ▶ BMS 온도 보기                         │
│         빠른 액션: [텔레옵] [전장부] [스냅샷]          │
└───────────────────────────────────────────────────────┘
```
- **장점**: 숙련자 초고속, 키보드 중심, 확장 쉬움(모든 기능을 명령으로 등록). 미니멀.
- **단점**: 비전문가에겐 "뭘 칠지" 막막. 발견성(discoverability) 낮음 → 부가 내비 필요.
- **적합도**: ★★★☆☆ — 보조 기능(전역 ⌘K)으로는 ★★★★★, 메인 패러다임으로는 위험.

## 6안. 앱 런처 그리드 (App Launcher Grid)

스마트폰 홈처럼 카테고리/기능을 큰 아이콘 타일 그리드로. 탭하면 해당 화면 진입.

```
┌───────────────────────────────────────────────────────┐
│  로봇 테스트벤치          ● zenoh  ● 201 함께          │
├───────────────────────────────────────────────────────┤
│   ┌───────┐  ┌───────┐  ┌───────┐                     │
│   │ 🖥     │  │ 🚀    │  │ 🎮    │                     │
│   │ 시스템 │  │ 런치  │  │ 텔레옵 │                     │
│   └───────┘  └───────┘  └───────┘                     │
│   ┌───────┐  ┌───────┐  ┌───────┐                     │
│   │ ⚙     │  │ 🔋    │  │ 📈    │                     │
│   │ 모터  │  │ 전장부 │  │ 데이터 │                     │
│   └───────┘  └───────┘  └───────┘                     │
└───────────────────────────────────────────────────────┘
```

- **장점**: 직관·터치 친화적, 카테고리 동등 강조, 태블릿/현장 사용에 좋음.
- **단점**: 상태/실시간 정보가 랜딩에 안 보임(한 번 더 들어가야). 정보 밀도 낮음.
- **적합도**: ★★★☆☆ — 현장 태블릿용 대안. 데스크톱 상시 모니터링엔 비효율.

## 7안. 마스터-디테일 분할형 (Master–Detail Split)

좌측 리스트(프로파일/노드/토픽 등 "대상") 선택 → 우측에 상세·제어·플롯. 이메일 앱 구조.

```
┌───────────────────────────────────────────────────────┐
│ testbench   ● zenoh ● 201                       ⚙     │
├───────────────────┬───────────────────────────────────┤
│ 프로파일 / 노드    │  상세: swerve_controller          │
│ ▸ _autostart  ●   │  상태: active                     │
│ ▸ 텔레옵      ●   │  ┌─ 명령 인터페이스 ─┐            │
│ ▸ 모터테스트  ○   │  │ /cmd_vel  [Twist 폼]│            │
│ ─ 노드 ─          │  └────────────────────┘            │
│ • robot_state ●   │  ┌─ joint_states 플롯 ─┐           │
│ • controller_mgr● │  │   ╱╲╱╲              │           │
│ • daly_bms    ○   │  └─────────────────────┘           │
└───────────────────┴───────────────────────────────────┘
```
- **장점**: "대상 선택 → 제어/관찰" 흐름이 명확. 노드/프로파일 단위 운영에 강함.
- **단점**: 카테고리(기능군) 구분이 약함. 여러 대상 동시 비교 어려움.
- **적합도**: ★★★★☆ — 런치 오케스트레이션 페이지에 특히 적합한 하위 패턴.

## 8안. 가이드 위저드 / 시나리오 단계형 (Guided Workflow)

"테스트 시나리오"를 단계로 안내. 전장부 점검 → 모터 점검 → 텔레옵처럼 절차 중심.

```
┌───────────────────────────────────────────────────────┐
│  테스트 시나리오: 출고 전 점검            ● zenoh ● 201 │
├───────────────────────────────────────────────────────┤
│  ①인프라 ─●─ ②전장부 ─●─ ③모터 ─◉─ ④텔레옵 ─○─ ⑤완료 │
├───────────────────────────────────────────────────────┤
│  현재 단계 ③ 모터 점검                                 │
│   • controller 활성화      [✔ 완료]                    │
│   • joint_states 플롯 확인 [확인 중… ╱╲╱╲]             │
│   • 온도 임계 < 60℃        [✔ 48℃]                     │
│                                                       │
│            [ 이전 ]              [ 다음 단계 ▶ ]        │
└───────────────────────────────────────────────────────┘
```
- **장점**: 반복 테스트 표준화, 누락 방지, 결과 자동 기록(자산화)와 결합 강력. 신규자 친화.
- **단점**: 자유 탐색 어려움, 시나리오 정의 선행 필요. 일상 모니터링엔 경직.
- **적합도**: ★★★★☆ — "전장부 테스트/출고 점검" 같은 정형 절차의 별도 모드로 탁월.

## 9안. 벤토 그리드 위젯 보드 (Bento / Widget Board)

랜딩이 재배치 가능한 위젯 보드. 사용자가 원하는 카드(플롯/상태/명령버튼)를 배치, 스냅샷으로 저장.

```
┌───────────────────────────────────────────────────────┐
│ 내 보드 ▼   [편집] [스냅샷 저장]        ● zenoh ● 201  │
├───────────────────────────────────────────────────────┤
│ ┌─ joint_states ─┐ ┌─시스템─┐ ┌─ 빠른명령 ─────┐      │
│ │   ╱╲╱╲╱        │ │CPU 23%│ │ [▶텔레옵][■정지]│      │
│ │                │ │온도47℃│ │ [cmd_vel 폼]   │      │
│ └────────────────┘ └───────┘ └────────────────┘      │
│ ┌─ BMS 대시보드 ──────────┐ ┌─ 201 상태 ─┐            │
│ │ V:54.2 I:3.1 SOC:82%    │ │ ● 함께      │            │
│ │ 셀온도 ▁▂▃▅             │ │ control ●  │            │
│ └─────────────────────────┘ └────────────┘            │
└───────────────────────────────────────────────────────┘
```
- **장점**: 완전 맞춤형, 스냅샷 기능과 1:1 매핑, 테스트별 보드 재현. 정보 밀도/유연성 최고.
- **단점**: 구현 난도 최상(그리드 레이아웃 엔진+위젯 레지스트리). 초기 빈 보드 진입 장벽.
- **적합도**: ★★★★☆ — "스냅샷으로 동일 구성 재현" 요구와 정확히 일치. 단 후기 Phase 적합.

## 10안. NOC 상태월 / 빅스크린 모니터 (Status Wall)

대형 모니터/벽면 표시 가정. 큰 상태 타일로 로봇 전체를 감시. 제어는 보조.

```
┌───────────────────────────────────────────────────────┐
│  ROBOT TESTBENCH — LIVE                  2026-06-09     │
├───────────────────┬───────────────────┬───────────────┤
│   ZENOH           │   컨트롤러 201     │   배터리       │
│   ● ONLINE        │   ● 함께 · 정상    │   82%  54.2V  │
├───────────────────┼───────────────────┼───────────────┤
│   CPU/온도 (202)  │   joint_states     │   진단         │
│   ▁▂▃▂▁ 23% 47℃  │   ╱╲╱╲╱╲          │   ● OK  ▲1경고 │
├───────────────────┴───────────────────┴───────────────┤
│  하단 빠른제어: [▶ 텔레옵] [■ 전체정지] [상세 →]       │
└───────────────────────────────────────────────────────┘
```
- **장점**: 한눈 감시 최강, 다인 공유/시연에 적합, 이상징후 즉시 포착.
- **단점**: 세밀 조작 불편(별도 제어 화면 필요), 작은 화면 부적합.
- **적합도**: ★★★☆☆ — 시연/모니터링 전용 뷰로 가치. 작업 메인으론 보조.

- **랜딩(홈) = 2안 Toss 대시보드** (상태 카드 + 빠른 시작 + 즐겨찾기 플롯)
- **데이터 페이지 = 3안 도킹 워크스페이스** (PlotJuggler 대체, 스냅샷 저장)
- **전역 보조 = 5안 ⌘K 커맨드 팔레트** (숙련자 가속)
- **확장(후기) = 8안 위저드**(출고 점검 시나리오) + **9안 위젯 보드**(스냅샷 재현)

이 합성은 "비전문가도 쉽게(2·6), 숙련자는 빠르게(3·5), 절차는 표준화(8), 구성은 재현(9)"을 단계적으로 충족한다.
